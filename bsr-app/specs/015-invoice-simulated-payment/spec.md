# 电子发票与虚拟付款

## 依据与范围

2026-10-27 确定在既有雪具租赁流程中增加发票查询和虚拟付款。沿用 NOK、八个业务模块及既有计费规则。同步课程设计书的用例、流程、图表、数据字典和界面设计。

## 设计与取舍

用户批准的流程：确认合同 → 查看电子账单 → 模拟付款 → 门店发放 → 查询凭证。只增加静态显示无法完成操作演示；接入真实支付超出虚拟付款要求。因此在既有租赁模块实现持久化模拟交易和从真实费用汇总的发票预览，无支付服务、税务接口、新业务表或新依赖。

“查看发票”显示课程演示电子账单，包含稳定单号、合同、门店、顾客、约定租期、雪具日租金快照、逐笔初始/补缴/退款费用、成功付款/退款、待付/待退、交易时间和来源。不能把合同应付额当成未付额，不能把失败流水计入已付，不能把演示单据写成真实税务发票。变更后的金额以费用事实为准，不重新按现价计算。

顾客只对本人已确认合同的未结清 INITIAL/SUPPLEMENT 费用模拟付款，选择成功或失败，不收集银行卡，不扣款。取消不提交。金额、交易类型、操作身份、时间由服务器决定。成功沿用既有结算/待发放状态转换；失败可以换新请求重试。同一请求重放返回原结果，改结果或跨费用复用请求号冲突。不同请求并发也只能付清一次。员工继续通过原入口登记外部付款/退款。

## 数据与权限

V008 在 payment_transaction 增加来源和模拟操作账号；员工登记字段允许仅在模拟交易中为空，用数据库 CHECK/FK 保证身份来源一致。历史记录默认为 EXTERNAL，保留原值、原员工和外部交易幂等规则。模拟由真实顾客账号审计，不伪造员工。顾客归属、角色、门店、Session/CSRF、合同状态在后端强制检查。费用和交易持久化、状态与成功审计同一短事务，锁既有合同根。

## 页面

小程序合同详情增加“查看发票”和“模拟付款”入口，使用独立发票页面，避免把支付表单堆进合同详情。发票页明确提示演示、不扣款，呈现成功、失败、取消、重试和查询最新状态。后台合同详情可展开同一发票，并标识顾客模拟流水与员工外部登记。金额均使用服务端十进制字符串。

## 验证与边界

真实隔离 MySQL 验证历史迁移、来源约束、金额、防重复、不同连接并发、审计回滚、归属/跨店、未确认/零金额/退款拒绝、CSRF。小程序与 Web 验证用户行为、失败数据保留、失效清空、原有流程及构建；真实浏览器检查手机/桌面布局。微信编译、临时预览与真机结果分别记录；只有真实证据才通过。沿用已付服务器，不新增费用。
